# ADR-0008：P0 只导出 PNG，PDF/SVG 后置

- 状态：Accepted（设计基线）
- 日期：2026-11-06
- 关联：`docs/architecture.md` 第 2.7、13 节；`docs/algorithm-design.md` 第 13-14 节；AC-20 至 AC-23

## 背景

原题要求至少支持 PNG 或 PDF 中的一种，并确保导出包含网格、色号且可独立阅读。已确认 P0 使用 PNG。未来若做 PDF，必须避免与预览分叉，并处理中文字体、分页和纸张尺寸。

## 可选方案

| 方案 | 实现成本 | 输出质量/可控性 | 风险 | 结论 |
| --- | --- | --- | --- | --- |
| Canvas → PNG `toBlob` | 低 | 与预览同源、像素可控 | 大图受 Canvas 内存限制 | **P0 选择** |
| 浏览器打印为 PDF | 最低 | 受页边距/用户设置影响 | 不可复现，不适合唯一交付 | 不采用 |
| jsPDF | 中低 | 可控但字体/布局能力有限 | 中文嵌入和复杂图例成本 | 备选 |
| pdf-lib | 中高 | 分页、矢量线、嵌入字体可控 | 需要字体子集/许可与额外包 | P2 推荐 |
| SVG 导出 | 中 | 矢量、可再编辑 | 字体/打印机兼容不确定 | P2 可选 |

## 决策

- P0 只实现 PNG。
- PNG 必须由 `RenderScene` 在离屏 Canvas 重绘，不允许截取网页预览。
- 每格至少 40 导出像素；编码使用 `canvas.toBlob`，下载使用 Blob/object URL。
- 导出前捕获 `stateVersion`，输出文件名包含尺寸和色盘版本。
- P2 PDF 优先使用 `pdf-lib` 从同一 `RenderScene` 生成矢量页面；如果中文字体嵌入不可接受，则嵌入高分辨率栅格页面作为保底。
- 不把 `pdf-lib` 加入 P0 运行依赖，不做“看起来能下载但内容不完整”的 PDF 占位。

## 理由

1. PNG 能直接满足原题和 P0 验收，且离屏 Canvas 与我们现有渲染核心一致。
2. Canvas `toBlob` 比 `toDataURL` 更节省中间字符串内存，下载链路简单。
3. 浏览器打印不可控，不能保证断网后仍能复现同一图纸。
4. PDF 的字体嵌入、分页和精确打印是独立工程，不应挤占 P0 的可读性验证。
5. 同一 `RenderScene` 为未来 PDF/SVG 保存了复用基础。

## 代价与限制

- P0 不提供矢量输出和物理 1:1 打印保证；与 D-04 一致。
- PNG 大图占内存；需要导出像素预算、失败重试和提示。
- PNG 字体依赖系统字体，跨设备像素可能略有差异；色号/网格/内容语义必须一致。
- PDF P2 会引入额外包和字体资源；需另做许可、子集化和分页校验。

## 验证方式

- PNG 文件头、尺寸、网格、色号、图例、空位和来源脚注通过独立查看器验收。
- 预览与导出抽取 10 格核对一致。
- 导出期间编辑不会改变本次快照。
- 导出失败不会下载 0 字节文件，也不会清空当前图纸。
