# ADR-0009：色盘快照、格子色号索引与源色共存

- 状态：Accepted（设计基线）
- 日期：2026-11-06
- 关联：`docs/data-model.md` 第 3-7 节；FR-05、FR-07、FR-12、FR-16；D-02、D-06

## 背景

图纸需要逐格追溯官方色号，同时要支持编辑、品牌重映射和工程恢复。若每个格子直接保存可变颜色对象或只保存色号字符串，容易出现：
- 同一色号在不同格子中颜色值不一致；
- 品牌重映射直接翻译色号导致错误；
- 色盘版本更新后索引/颜色含义漂移；
- 工程恢复时无法确认色盘版本。

## 可选方案

| 方案 | 追溯性 | 重映射 | 存储成本 | 风险 | 结论 |
| --- | --- | --- | --- | --- | --- |
| 每格存完整 RGB + 名称 | 可读 | 可从 RGB 重算 | 冗余大 | 名称/RGB 可漂移 | 不采用 |
| 每格仅存官方 code | 可读 | 需查当前色盘，跨品牌易误译 | 小 | 同 code 在不同品牌不通用 | 不采用 |
| 每格存色盘索引 + 色盘引用 | 通过快照解析，可验证 | 从 `sourceRgb` 重算 | 小 | 依赖版本/checksum 校验 | **采用** |
| 每格存索引 + code + RGB | 最直观 | 仍需源色 | 最大 | 三份真相漂移 | 不采用 |

## 决策

- `BeadPattern.paletteRef` 保存品牌/系列/版本/checksum。
- 每格 `colorIndex` 指向已校验的 `Palette.colors` 数组。
- 每个自动生成格保存 `sourceRgb`：生成时是白底合成后的源色；P2 用它重映射，不从 Hama 色号硬翻。由空位转为手工色的格允许 `sourceRgb = null`。
- 空位为 `null`；不保存 `-1`、白色索引或空色号。
- 工程文件把 `pattern` 与 `paletteSnapshot` 分开放；运行时由 `PaletteRepository` 解析引用，校验 checksum。
- 若版本不匹配：提示使用旧快照或重新匹配，禁止静默换色。

## 理由

1. 索引使 16,384 格保持紧凑，避免重复存 67 色对象的副本。
2. checksum 使“索引含义”可验证，版本相同但内容被替换会被识破。
3. `sourceRgb` 保留重新匹配的必要输入，满足 P2 品牌重映射不硬翻色号。
4. 空位用 `null` 从模型层阻止“透明变白豆”的误实现。
5. 工程文件分离色盘快照，符合 FR-12 的版本可追溯要求。

## 代价与限制

- 运行时必须能解析指定 `PaletteRef`；旧版本缺失时需要快照或明确阻止恢复。
- 索引不是跨色盘通用 ID；品牌重映射必须重新计算并写入新 `paletteRef`。
- 手工由空位转成的色格没有自动采样源色，`sourceRgb` 为 null；P2 全量重映射时无法推导，只能保留并报告。
- 导出必须通过当前色盘解析 code；不能把索引直接当色号显示。

## 验证方式

- 67 色自匹配后每格索引解析出的 code 与色盘一致。
- 修改色盘数组中任意颜色但保留相同 checksum 会被校验拒绝（或重新计算 checksum 后视为新版本）。
- 工程恢复版本不匹配时出现选择，不静默改色。
- 空位永远没有 code，统计不把空位算作白色豆。
