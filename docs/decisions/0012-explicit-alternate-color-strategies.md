# ADR-0012：RGB 与 Floyd–Steinberg 仅作为显式备选策略

- 状态：Accepted（P05 可选实现）
- 日期：2026-11-06
- 关联：ADR-0004、ADR-0006、`docs/algorithm-design.md` 第 8-9 节、FR-06、FR-16

## 背景

P05 要求提供统一的颜色匹配接口，至少支持 RGB 欧氏距离和 CIELAB ΔE76，并实现可选 Floyd–Steinberg。已冻结的 P0 默认仍是 CIE76 + 无抖动；备选策略不能改变默认业务口径。

## 可选方案

| 方案 | 结果 | 对图纸的影响 | 结论 |
| --- | --- | --- | --- |
| 只实现 CIE76 | 最少代码 | 无法验证统一匹配接口的可替换性 | 不满足本轮交付 |
| RGB、CIE76 与抖动都成为默认轮换策略 | UI 复杂、结果不可预期 | 材料清单会随隐式策略变化 | 拒绝 |
| RGB/CIE76 经显式 `matcher` 选择；抖动经显式 `dithering` 选择 | 默认不变，可独立测试和复现 | 用户明确选择后才改变 | **采用** |

## 决策

1. `cie76` 继续是 P0 默认匹配策略。
2. `rgb-euclidean` 作为可替换策略实现，仅用于显式比较或后续“匹配策略切换”；不冒充 CIE76 结果。
3. `floyd-steinberg` 作为 P2 可选策略实现，默认 `none`。扫描顺序固定为行优先，误差在 sRGB 字节空间按 7/16、3/16、5/16、1/16 扩散。
4. 抖动不跨越空位传播误差；`sourceRgb` 始终保存抖动前的白底合成采样色，便于换色盘重映射。
5. `ciede2000` 仍只在类型中预留，本版本工厂明确拒绝，不声称已支持。

## 理由

- 默认 CIE76 保持已确认验收结果与材料清单口径。
- RGB 距离实现简单、速度高，适合作为策略可替换性的验证样本；实际测试已找到其与 CIE76 选择不同 Hama 色号的输入。
- 抖动会提高分散色数量、增加视觉噪点，对实体拼豆采购并非无条件更好，因此必须允许关闭并由用户显式选择。
- 固定扫描顺序、固定权重和固定 `sourceRgb` 规则使结果可重复、可解释。

## 代价与限制

- 抖动后的单格不再保证是最近色；材料种类可能增加。
- RGB 与 CIE76 对同一输入可能产生不同色号和清单，UI 必须显示当前策略名。
- Floyd–Steinberg 仍是 O(格数 × 色盘数)，但常量和视觉噪点的验证成本高于无抖动。
- CIEDE2000 的公式复杂度、独立数值矩阵和版本争议成本更高，本版本不做。

## 验证方式

- RGB 与 CIE76 自匹配、平局按官方 code、空色盘拒绝、重复调用确定性。
- 深蓝样本 `[0,0,90]` 在 Hama 盘上分别选择 `116` 与 `08`，证明策略不是换名不换实现。
- 8×8 灰色图在二色测试盘上无抖动只用 1 色，抖动后使用 2 色。
- 抖动结果重复调用逐格一致，透明空位保持 `null`。
