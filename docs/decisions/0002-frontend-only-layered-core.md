# ADR-0002：纯前端、分层架构与可替换核心

- 状态：Accepted（设计基线）
- 日期：2026-11-06
- 关联：`docs/architecture.md` 第 3、4、5 节

## 背景

图片仅在用户本机处理，P0 不需要账号、云存储、多人协作或服务端颜色计算。72 小时内最需要保证的是：图片不离开浏览器、核心算法可独立测试、UI 可以与处理链路解耦。

## 可选方案

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 纯前端单页 + 纯 TS 领域核心 | 本地隐私、零后端延迟、部署简单、核心可单测 | 受浏览器内存/CPU限制；无云保存 | 采用 |
| 前端上传后端处理 | 可处理更大图、集中审计色盘 | 需要服务、上传隐私、网络失败、部署与成本；72h 不匹配 | 不采用 |
| 全部逻辑写在 React/Canvas 组件内 | 起步快 | 无法独立测试、预览/导出易分叉、状态耦合 | 不采用 |
| 微服务/数据库/外部 AI | 未来可扩展 | 与 P0 需求无关，增加合规和故障面 | 明确不引入 |

## 决策

采用纯前端分层架构：

```text
UI（React）
  -> 应用层（reducer、生成/导出编排、历史）
    -> 领域核心（纯 TypeScript）
    <- 基础设施适配器（解码、色盘、Canvas、Blob）
```

- 领域核心不依赖 React、DOM、Canvas、File 或网络。
- 图片处理由 `ImageDecoder` 适配器输出 `RgbaImage`；核心接收纯数据。
- 色盘通过 `PaletteRepository` 装载；匹配器通过 `ColorMatcher` 接口替换。
- 预览、统计和导出只读取 `PatternDocument`。
- 工程保存使用本地 JSON；不做账号和云同步。

## 理由

1. P0 的图片、色盘和导出都可以在本地完成；服务器不增加用户价值，反而增加失败点。
2. 领域核心可脱离页面测试，直接满足“核心算法独立测试”的工程要求。
3. 适配器边界让 Canvas 预览、离屏导出和未来 Worker 共用同一算法，而不是复制业务逻辑。
4. 不引入数据库/后端使交付部署更简单，符合 72 小时约束。

## 代价与限制

- 浏览器是唯一运行环境；大图受内存和 Canvas 上限约束。
- 无法提供云保存；P1 仅做本地 JSON。
- 色盘装载和字体必须随应用本地化，运行时不能依赖第三方接口。
- 领域层要主动避免浏览器类型；这增加少量类型转换，但换来可测试性。
- 未来若加入后端，必须通过新适配器/ADR，不能把网络请求塞进领域函数。

## 验证方式

- `domain/` 在 Vitest 中无 DOM 环境运行。
- 用测试替身替换 `ImageDecoder` 和 `PaletteRepository` 完成全链路单元测试。
- 断网情况下打开已加载页面可完成生成与 PNG 导出（不依赖远程资源）。
