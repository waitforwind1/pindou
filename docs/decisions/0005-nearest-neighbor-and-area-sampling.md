# ADR-0005：P0 最近邻，P1 增加区域平均

- 状态：Accepted（设计基线）
- 日期：2026-11-06
- 关联：`docs/algorithm-design.md` 第 4-6 节；FR-04、FR-15、AC-06、AC-P1-07

## 背景

用户既可能上传硬边像素画，也可能上传普通照片。两种输入需要不同的缩放策略；如果只做平滑，像素画会糊；如果只做最近邻，照片会随机丢失细节。

## 可选方案

| 采样 | 像素画 | 照片 | 实现成本 | 结论 |
| --- | --- | --- | --- | --- |
| 最近邻 | 保留硬边，最佳 | 降采样会产生锯齿/丢点 | 低 | P0 默认 |
| 区域平均 | 会破坏硬边和原本像素 | 保留整体明暗，较平滑 | 中 | P1 显式模式 |
| 双线性 | 会制造原图没有的过渡色 | 较平滑，但可能过度柔化 | 低 | 不采用为默认 |
| 双三次/锐化 | 像素画易过冲 | 细节好看但引入光晕 | 中高 | 不在 P0/P1 范围 |

## 决策

- P0 固定最近邻；普通照片也必须安全处理，但显示质量告警，不承诺自动优化。
- P1 提供“照片”模式，使用预乘 alpha 的区域平均。
- 目标尺寸始终严格等于用户选择；contain 只产生空位留边，不改变目标行列数。
- 区域平均在线性光中求平均，先按 alpha 预乘，再合成白底，避免透明边黑边/彩边。
- 不使用浏览器默认平滑作为算法真相；核心采样必须纯 TypeScript 可测试。

## 理由

1. 最近邻是像素画保真的唯一合理默认，也最符合“每个格子对应实体色”的可解释性。
2. 区域平均对普通照片有实际价值，但它是模式切换，不应偷偷改变 P0 结果。
3. 线性光 + 预乘 alpha 可以避免 gamma 编码空间平均和 transparent black 造成的颜色偏差。
4. contain 的坐标规则能用 8×4→64×64 的固定测试向量直接验收。

## 代价与限制

- P0 上传照片会得到有损的硬采样，必须用告警管理预期；这不是故障。
- P1 区域平均需要处理分数边界和 alpha 权重，算法与测试成本高于最近邻。
- 两种模式的结果可能明显不同；UI 必须显示当前模式和“切换会改变边缘/噪点”的提示，但不能自动改用户选择。
- P0 最近邻与 P1 区域平均的透明合成分别使用显示空间/线性光策略，必须在算法文档中固定，不能在同一模式下混用。

## 验证方式

- 8×4→64×64 内容区为 64×32、上下各 16 行空位。
- 硬边图最近邻不产生原图没有的过渡色。
- P1 透明边缘不出现黑边/彩边；两种模式在照片样本上结果不同。
- 全透明输入仍阻止生成。
