# ADR-0003：Canvas 2D 作为图纸主渲染方案

- 状态：Accepted（设计基线）
- 日期：2026-11-06
- 关联：`docs/architecture.md` 第 2.2、13 节；`docs/algorithm-design.md` 第 13 节

## 背景

图纸最多 128×128 格，并且每个有豆格需要显示色号、网格线、行列号和图例。预览还要支持缩放、滚动、选中和 P1 编辑；导出必须与预览一致并包含完整色号。

## 可选方案

| 方案 | 4096-16384 格表现 | 可访问性/交互 | 导出一致性 | 结论 |
| --- | --- | --- | --- | --- |
| Canvas 2D 单画布 | 好；一次绘制命令完成 | 命中测试需自写；需额外 DOM 摘要 | 离屏同源绘制 | 改善为双 Canvas |
| Canvas 静态层 + 交互覆盖层 | 好；hover/选中不重绘底图 | 命中数学坐标；DOM 面板补充语义 | 共用场景布局 | **采用** |
| SVG 全量节点 | 16k+ 格子与文字节点易卡 | 天然 DOM 事件/可访问性 | 矢量清晰，PNG需再栅格化 | 不采用 |
| DOM/CSS Grid 方块 | 大图 DOM 数量爆炸 | 简单但性能差 | 截图路径不可控 | 不采用 |

## 决策

- 图纸主画布使用 Canvas 2D。
- 采用双层 Canvas：静态网格/色号/标尺一层，选中/悬停/接缝参考一层。
- UI、图例文本、材料清单、错误提示使用 DOM；Canvas 旁提供文字摘要和可访问清单。
- 用纯数据 `RenderScene` 描述绘制内容；预览和离屏 PNG 都通过同一布局和渲染核。
- P2 如需 SVG/PDF，新增场景适配器，不把主画布改成全量 SVG。

## 理由

1. 格子、文字和网格在 Canvas 上一次批量绘制，避免数万 DOM 节点。
2. 双 Canvas 把 hover 从“全图重绘”变成“覆盖层重绘”，交互成本可控。
3. `RenderScene` 让“画什么”和“用 Canvas 画”分离，未来可生成 PDF/SVG。
4. 导出能从不可变 `PatternDocument` 重新布局，避免网页截图与用户缩放影响。
5. DOM 材料清单和文字摘要补足 Canvas 的语义缺口。

## 代价与限制

- 必须自己实现格子命中、缩放、视口裁剪和文本布局。
- Canvas 不自动提供 DOM 可访问性；验收不能只看“有 Canvas”，必须有可读摘要和 DOM 清单。
- 大图导出仍受 Canvas 像素/内存上限，需要导出前预算和失败提示。
- 预览低缩放时可能隐藏色号，但导出必须固定完整显示；两条路径由同一场景规则控制，不能失去“完整色号”验收。
- 字体按本地系统字体渲染，跨机器像素不完全一致；不做跨平台逐字节 PNG 哈希断言。

## 验证方式

- 64×64 和 128×128 画布滚动/缩放连续，不因 hover 重绘底图。
- 100% 预览与导出抽查 10 格，色号/色块/空位一致。
- 导出图脱离网页可读，并包含完整网格、色号、行列号和图例。
