# 拼豆图纸生成工具：验收标准

| 项目 | 内容 |
| --- | --- |
| 文档版本 | v1.1（P02 深化） |
| 日期 | 2026-11-06 |
| 依据 | `docs/requirements.md` v1.1、`docs/product-design.md` v1.0 |
| 适用对象 | P0 交付验收；P1 作为增强项单独验收 |
| 默认浏览器 | 最新版 Chrome / Edge 桌面版 |
| 默认色盘 | Hama 2026 Midi Colour palette，Solid 67 色 |
| 基线状态 | P0 范围不变；P02 新增 P1/P2 验收，不与原题强制项混算 |

## 1. 验收原则

1. **黑盒优先**：能在界面操作验证的，不依赖查看实现代码。只有色盘数据、匹配确定性和“每格均可追溯”允许用开发自测/数据检查辅助。
2. **同一状态**：预览与导出必须来自同一份图纸状态；不能预览正确而下载后换色。
3. **格子级追溯**：有效格不是“看起来像某个颜色”，而是必须对应色盘中的官方色号和名称。
4. **独立性**：导出的 PNG 必须在断网、关闭网页、换图片查看器的条件下仍能读懂。
5. **真实性优先**：任何未核验色号、临时 RGB 表或不完整来源，均判定为 P0 不通过。

## 2. 测试准备

### 2.0 已确认基线

- 首发品牌：Hama；色盘：官方 2026 Midi Solid 67 色。
- P0 目标尺寸：32/48/64 预设；默认 64×64。
- P0 导出：PNG。
- 透明：`A<128` 为空位，`A>=128` 白底合成后匹配。

以上为 2026-11-06 确认项。任何验收不得把它们重新变成“可选”，也不得用 P1 功能抵扣 P0。

### 2.1 环境

- 桌面分辨率：1440×900 或更高。
- 浏览器缩放：100%。
- 网络：生成阶段可断网测试；应用不得依赖远程 API。
- 颜色设置：使用默认 sRGB 显示配置；记录显示器/系统差异，不据此否定色号正确性。
- 构建版本：记录提交 SHA、色盘版本 `hama-2026-midi-solid-67`、测试日期和测试人。

### 2.2 固定测试文件

| 文件 | 内容 | 目的 |
| --- | --- | --- |
| `fixture-alpha-4x4.png` | 4×4；依次包含 A=0、A=1、A=127、A=128、A=255、白色、黑色、纯色块 | 透明阈值与合成 |
| `fixture-pixel-32x32.png` | 32×32 硬边像素画，含透明背景和至少 4 个色块 | 端到端正向流程 |

| `fixture-palette-64x64.png` | 64×64，67 个色块各占一个独立像素，其余透明；每个像素使用色盘自身 `displayRgb`，目标 64×64 时按 1:1 取样 | 自匹配与逐格色号 |
| `fixture-landscape-8x4.png` | 8×4 硬边像素图，含透明角 | contain、最近邻与比例 |
| `fixture-all-transparent.png` | 全透明 | 阻止空图纸导出 |

## 3. P0 验收项

### AC-01 上传 PNG 并进入生成流程

**优先级**：P0（对应 M1）

**Given** 用户打开工具且尚未选择文件  
**When** 用户选择合法 `fixture-alpha-4x4.png`  
**Then** 页面显示文件名、源图尺寸 4×4、原图预览，并允许选择目标尺寸和生成图纸。

**判定**：无白屏、无控制台阻塞错误；文件内容不会被发送到网络。

### AC-02 支持常见图片格式并拒绝无效文件

**优先级**：P0（对应 M1）

**步骤**

1. 依次上传 PNG、JPEG、WebP 合法文件。
2. 上传 `fixture-corrupt.png`。
3. 上传一个文本文件并改名为 `.png`。
4. 上传超过 20 MB 或超过 16,777,216 像素的文件。

**通过**

- 三种合法格式均能解码并预览。
- 损坏/伪装的图片显示明确错误，不能进入“生成成功”状态。
- 超限文件被拒绝，提示原因和可选处理方式。
- 错误提示不会泄露无意义的堆栈或把失败显示成成功。

### AC-03 正确读取像素颜色

**优先级**：P0（对应 M2）

**Given** `fixture-pixel-64x64.png`，内容为已知 RGB 的硬边像素，目标尺寸 64×64、1:1 取样  
**When** 系统读取并显示目标格颜色  
**Then** 有效格的颜色来源与源图对应像素一致，且不会因 CSS 滤镜、透明容器或预览缩放而改变匹配输入。

**证据**：对 3 个已知像素分别核对 R/G/B；至少覆盖纯白、纯黑和一个中间色。

### AC-04 透明像素规则正确

**优先级**：P0（对应 M2、M8）

**步骤**：上传 `fixture-alpha-4x4.png`，使用 64×64 预设并保持 contain，生成图纸。

**通过**

- 源图 A=0 和 A<128 的区域最终为空位，不出现色号。
- A>=128 的区域为有效格，具有一个色盘色号。
- 检查图纸状态/材料统计时，空位不计入豆数。
- 上传全透明图时，系统阻止生成并提示“没有有效像素”。
- UI 或说明中能看到“半透明像素按 50% 阈值并合成白底”的口径。

**反例**：透明格被匹配成白色、黑色或任意实体色，判失败。

### AC-05 目标尺寸可控制且网格尺寸正确

**优先级**：P0（对应 M3）

**步骤**

1. 分别选择 32×32、48×48、64×64 预设并生成。
2. 检查预览/导出模型的行数与列数。

**通过**

- 每个预设均生成精确 `N×N` 网格，不因图片比例悄悄改变目标尺寸。
- 页面明确显示当前目标宽高和有效豆数。
- 默认值为 64×64。

### AC-06 contain 与最近邻采样符合声明

**优先级**：P0（对应 M3）

**Given** `fixture-landscape-8x4.png`（宽高比 2:1，含透明角）  
**When** 选择 64×64、默认 contain、默认最近邻并生成  
**Then**

- 内容按 2:1 比例落入中间的 64×32 区域，水平居中。
- 上下各 16 行保持空位（由半透明阈值处理后的结果决定，不能误填色）。
- 硬边不被平滑成过渡色；无色块被横向拉伸为 64×64。

**证据**：核对第 1、16、32、48、64 行的格状态，并检查原图透明角位置。

### AC-07 提供真实 Hama 基础色盘

**优先级**：P0（对应 M4、M5）

**Given** 打开生成页或色盘说明入口  
**When** 查看色盘信息  
**Then** 页面清楚显示：

- 品牌：Hama
- 系列：Midi
- 色盘版本：2026 Solid 基础实色
- 颜色数量：67
- 官方色卡来源页链接
- “参考色/非官方 RGB”的准确性说明

**判定**：不能只显示“Hama 色盘”而没有版本和来源。

### AC-08 色盘条目结构完整且唯一

**优先级**：P0（对应 M4、M6）

**检查方式**：读取发布包中的色盘数据文件并运行校验。

**通过条件**

- 恰好 67 个 Solid 条目（若产品决定缩减，必须另立范围变更，不能静默少色）。
- 每个条目都有非空且唯一的 `code`、官方英文 `name`、`displayRgb`、来源文档和页码/版次。
- 无重复色号；无空名称；无 `unknown`、`custom`、`generated` 等占位值。
- 所有条目标记为 `official-chart-derived`，不标记为“官方 RGB”。
- 不允许把透明、夜光、Bio、Mini/Maxi 专属特殊效果色混入这 67 色而不分组。

### AC-09 色号与颜色可核验

**优先级**：P0（对应 M6、M9）

**人工核对步骤**

1. 打开官方色卡页与固定版次 PDF。
2. 抽查至少 10 个条目，覆盖浅色、深色、彩色和无彩色。
3. 对每个抽查项核对官方色号、英文名和色块位置。
4. 检查色盘数据记录的 PDF SHA-256 与来源记录一致。
5. 检查每个 `displayRgb` 都有采样记录（取样区域/方法/日期）。

**通过**

- 抽查项全部能在官方 PDF 中找到对应编号和名称。
- 颜色值可重复采样，且与官方色块视觉一致。
- 无编造色号、无把网店照片冒充官方色卡。

**失败示例**：中文译名存在但官方编号不存在；用“近似色”自造 999 号；把屏幕取色值称为官方标准。

### AC-10 最近色匹配结果正确

**优先级**：P0（对应 M7）

**步骤**

1. 上传 `fixture-palette-64x64.png`；67 个色块各占一个独立像素，其余透明。
2. 目标 64×64，最近邻且 1:1 取样，生成。
3. 对 67 个色块逐块核对输出色号。
4. 用独立的 CIELAB 参考计算器，对至少 12 个非色盘 RGB 样本核对匹配色号。

**通过**

- 67 个自测色块全部匹配回自身色号。
- 参考计算器结果与产品结果一致；若不同，产品必须有明确、可复现的容差说明且不影响“最近色”定义。
- 匹配基于 CIELAB/CIE76，而不是 RGB 欧氏距离；不得用肉眼“看起来差不多”代替计算。

### AC-11 匹配结果稳定且无随机性

**优先级**：P0（对应 M7）

**步骤**：同一输入、同一色盘、同一设置连续生成 3 次，比较每格色号。

**通过**

- 三次逐格色号完全一致。
- 相同距离时按官方色号升序稳定选择。
- 刷新页面后仍一致。

### AC-12 每个有效格都有合法色号

**优先级**：P0（对应 M8）

**检查方式**：对图纸内部状态/可测试导出执行遍历。

**通过**

- `cell != null` 的所有格子，`paletteCode` 均存在于当前 67 色色盘。
- 每个非空格都有官方英文名称、显示色和来源记录。
- 若当前版本实现颜色统计，则非空格数量必须等于统计总豆数；未实现统计时，该一致性由 AC-P1-01 单独验收，不反向阻断 P0。
- 不存在“已上色但没有色号”的格子。

**失败判定**：任意一个有效格只有 RGB、没有色号，或色号不在色盘，P0 直接不通过。

### AC-13 空位与有效格可区分

**优先级**：P0（对应 M8）

**通过**

- 空位有不同于所有豆色的底色/纹理，且不带色号。
- 深色豆与空位、浅色豆与空位都不会混淆。
- 图例/统计把空位排除在豆数之外，必要时单独显示空位数。

### AC-14 来源与准确性说明可见

**优先级**：P0（对应 M9）

**通过**

- 页面可访问“色盘来源/准确性说明”，至少在生成区和导出图脚注中出现来源指向。
- 说明包含官方色卡页 URL、色盘版本、取样日期、“参考色非官方 RGB”声明。
- 说明包含“不同屏幕、打印、材料批次和光线会造成颜色差异”的提示。
- 不出现“100% 官方色”“完全无色差”“保证与实物一致”等无法证明的表述。

### AC-15 生成完整拼豆网格图纸

**优先级**：P0（对应 M10）

**Given** 已生成 64×64 图纸  
**When** 用户查看预览  
**Then**

- 图纸覆盖全部 64×64 格，不因视口裁切丢失内容（可滚动/缩放查看）。
- 每个有效格使用对应色号颜色填充。
- 空位保持空位表现。
- 行列数量与目标尺寸一致。

### AC-16 网格线清晰且逐格存在

**优先级**：P0（对应 M11）

**通过**

- 每个相邻格之间有连续、可辨认的边界线。
- 每 5 或 10 格有更明显的主网格线，视觉层级清楚。
- 网格线颜色在浅色、深色、空位背景上都可辨认。
- 放大预览后，所有格边界仍连续；不因缩放出现断裂或覆盖色号。

**判定方式**：在 100% 导出图上抽查四个角、中心区域和相邻明暗色块；出现断线或整片不可见即失败。

### AC-17 每个有豆格内标记对应色号

**优先级**：P0（对应 M12）

**通过**

- 每个非空格子都显示与数据状态一致的官方色号。
- 色号文本位于格内，不跨格、不被网格线遮住、不覆盖到相邻格。
- 2 位和 3 位色号都能完整显示。
- 色号不依赖悬停提示或图例反查；导出图上能直接看到。

### AC-18 图纸色号可读

**优先级**：P0（对应 M13）

**通过**

- 导出 PNG 以 100% 打开时，抽查至少 30 个格子，色号能直接读出，无需放大。
- 文字与格底/描边的有效对比满足可读性；深色格用浅色字，浅色格用深色字，并带细描边。
- 文字最小有效字号不小于 12 导出像素；不裁切、不重叠。
- 不同颜色相邻时，网格和文字仍能区分。
- 若默认 64×64 图不能满足以上条件，P0 不通过。

### AC-19 行列定位与图例完整

**优先级**：P0（对应 M13）

**通过**

- 图纸有行号/列号，至少每 5 格标注一次。
- 图例列出所有实际使用的色号、官方名称和色块。
- 图例不把两个相近颜色合并。
- 标题区显示图纸宽高、有效豆数、空位数、色盘版本和生成时间。

### AC-20 下载按钮可用

**优先级**：P0（对应 M14）

**Given** 已成功生成图纸  
**When** 点击“下载图纸”  
**Then** 浏览器下载一个 `.png` 文件，按钮有进行中/成功/失败状态，文件名包含尺寸与色盘标识。

**失败处理**：下载失败时显示可重试提示；不能静默失败或下载 0 字节文件。

### AC-21 导出格式为有效 PNG

**优先级**：P0（对应 M15）

**通过**

- 文件头为 PNG 签名，扩展名 `.png`。
- 图片可被系统图片查看器、浏览器和至少一个独立图像工具打开。
- 文件不是 HTML/JSON 伪装成 PNG，不是空白图。
- 图像像素尺寸足够容纳全部格子和图例。

### AC-22 导出内容包含网格线与色号

**优先级**：P0（对应 M16）

**通过**

- 导出图包含完整网格线，而不只是颜色块矩阵。
- 每个有效格都有对应色号，且与当前预览一致。
- 导出图包含行列号和图例。
- 与预览抽取 10 个格子比对，色号、颜色、空位状态一致。

### AC-23 导出文件可独立阅读

**优先级**：P0（对应 M17）

**步骤**

1. 下载 PNG。
2. 关闭网页或断网。
3. 用独立图片查看器打开。
4. 仅凭图片完成一次 8×8 子区域的读图演练。

**通过**

- 不需访问网站、账号、在线色盘或外链即可理解图纸。
- 色号、网格、行列位置和图例在同一文件内。
- 图片没有因外部字体/图片资源缺失而出现空白文字或破图。
- 看图者能根据格内色号完成摆放，不需要回到网页。

## 4. P0 端到端验收场景

### E2E-01 标准像素画闭环

1. 上传 32×32 像素画（`fixture-pixel-32x32.png`）。
2. 选择 64×64。
3. 检查预览中内容按比例居中、透明区为空位。
4. 核对图例总豆数等于非空格数。
5. 下载 PNG。
6. 断网后用独立查看器打开，核对 10 个位置的色号和网格。

**结果要求**：AC-01、03、04、05、06、12、15-23 全部通过。

### E2E-02 色盘自匹配闭环

1. 上传由 67 个官方参考色组成的测试图。
2. 目标 64×64，生成。
3. 每个色块应映射自身色号。
4. 导出并逐块核对图例色号。

**结果要求**：AC-07 至 AC-12 全部通过。

### E2E-03 失败闭环

1. 上传损坏文件：错误提示，不进入导出。
2. 上传全透明图：阻止生成，提示。
3. 色盘数据校验失败（测试构建可注入）：禁止匹配和导出，不能伪造色盘。
4. 恢复正确文件/色盘后重新生成成功。

**结果要求**：错误可恢复，不丢当前图纸，不产生虚假色号。

## 5. P1 增强项验收（若实现）

P1/P2 不是原题 P0 的替代品。未实现时应明确标注“不在本次范围”，不能把 P0 验收降级为“可选”。

### AC-P1-01 颜色用量与材料清单

- 每个实际使用色号显示数量；总量等于非空格数。
- 修改图纸后统计即时更新。
- 导出图例与页面统计一致。

### AC-P1-02 自定义尺寸

- 可输入 8-128 的宽和高，生成精确尺寸。
- 0、负数、小数、超过上限、总格数超限时有明确错误。
- 修改尺寸后重新采样，不沿用旧网格。

### AC-P1-03 单格编辑

- 点击非空格可改为另一个真实色号或空位。
- 修改后颜色、色号、图例、统计和导出同步更新。
- 不能编辑出不存在于当前色盘的颜色。

### AC-P1-04 撤销/重做

- 连续编辑后撤销可逐步恢复，重做可再次应用。
- 新编辑会清空重做栈。
- 撤销/重做后统计和导出与当前状态一致。

### AC-P1-05 工程保存/恢复

- 保存 JSON 后刷新页面可恢复尺寸、每格色号、空位和色盘版本。
- 色盘版本不匹配时给出明确提示，不能静默换色。

### AC-P1-06 实体尺寸与底板估算

**Given** 已生成 64×64 图纸，默认 Hama Midi 中心距按 5 mm 展示  
**When** 打开“尺寸/底板”信息  
**Then**

- 成品估算显示 `64 × 5 mm = 320 mm` 宽和同高的计算过程或明确结果。
- 以 29×29 底板估算时，至少显示 3×3=9 块；以 57×57 底板估算时，至少显示 2×2=4 块。
- 明确标注“理论最少、未计重叠/拼接/留白”，并提供修改中心距或底板规格的入口。
- 页面把“成品尺寸”和“纸张打印尺寸”分开，显示 100% 打印提示。

**失败**：把估算值包装成官方物理尺寸；把底板块数说成精确所需而不加前提。

### AC-P1-07 照片友好采样

**Given** 上传 `fixture-photo.jpg`  
**When** 用户选择“照片”模式并生成  
**Then**

- 页面在生成前显示非像素画质量提示，但不强制拒绝。
- 照片模式使用预乘 alpha 的区域平均缩放；透明边缘不出现彩边。
- 像素画模式仍保持最近邻硬边，两种模式切换可见且结果不同。
- 照片模式不悄悄启用抖动、限色、抠图或伪造透明。
- 普通照片导入不会导致崩溃或空白输出；若无有效像素仍按原规则阻止。

**优先级**：P1；P0 只需安全解码、最近邻和清晰告警。

### AC-P1-08 编辑后颜色清单与导出同步

**Given** 已有 64×64 图纸并实现了单格编辑与颜色统计  
**When** 将 10 个 A 色格子改为 B 色，再将其中 2 个改为空位  
**Then**

- A 数量减少 10，B 数量增加 8，总豆数减少 2；三者与逐格遍历结果一致。
- 图例、材料清单、总豆数同步更新；空位不进入颜色清单。
- 连续撤销/重做恢复每一步的格子、数量和图例。
- 导出的 PNG 与当前状态一致，并与操作前的旧 PNG 不同。

**失败**：只重绘颜色不更新数量、清单单独缓存导致漂移、撤销只恢复画面不恢复数量。

### AC-P1-09 导出快照一致性

**Given** 已生成图纸且实现了编辑功能  
**When** 用户点击导出后在异步绘制期间修改一个格子  
**Then**

- 正在生成的 PNG 对应点击导出时的 `stateVersion`，不会混入新修改。
- 导出完成后再次导出，才反映新修改；页面明确提示“已导出旧版本”或自动排队重导。
- 同一状态下连续导出两次，格色、色号、图例、尺寸一致。

## 5.1 P2 增强项验收（仅当具备真实数据与实现）

### AC-P2-01 品牌色盘重映射

- 仅当存在第二个真实、已校验品牌色盘时才能启用。
- 切换必须按每格 `sourceRgb` 重新匹配，不得把 Hama 色号直接翻译成另一品牌色号。
- 空位保持空位；手工格默认保留并提示“未随品牌切换”，用户可显式选择全部重算。
- 切换后显示颜色损失/数量差异，图例、材料清单和导出均使用新品牌。
- 目标色盘缺失或未校验时禁用切换，不能出现虚构品牌选项。

### AC-P2-02 大图分板

- 给定图纸尺寸、单板规格和重叠规则，输出完整的板号、板内坐标和全局坐标。
- 每块板都有可独立打印的网格、色号和图例；板间接缝有明确标记。
- 不能把跨板格子静默裁掉；分板后总有效格数与分板前一致。
- 预览中的分板边界与导出图一致。

### AC-P2-03 匹配策略切换

- 用户看到的策略名称必须可解释：直接最近色、限色、抖动或 CIEDE2000 等不得混成一个“更准”按钮。
- 切换策略前显示影响和预计色数变化；用户确认后才替换当前结果。
- 导出图和元数据记录策略、色盘版本与参数；关闭/重开工程后可复核。
- 策略变化不得破坏色号可读性、空位规则和逐格实体色可追溯性。
